# Clifford

Geometric Algebra (a.k.a. Clifford algebra) package for Free Pascal compiler.

## Contents

| Unit | Algebra | Basis vectors |
|---|---|---|
| `cl2` | Cl(2,0), 2D Vectorspace geometric algebra | e1, e2 |
| `cl3` | Cl(3,0), 3D Vectorspace geometric algebra | e1, e2, e3 |
| `cl4` | Cl(4,0), 4D Vectorspace geometric algebra | e1 .. e4 |
| `cl13` | Cl(1,3), Spacetime algebra (STA) | g0 .. g3, g0^2 = +1 |

The units are generated by the [toolkit](#toolkit), which can produce any
Cl(p,q) with p + q up to 6.

## Usage

Install the `clifford.lpk` package in Lazarus, or add the units to your
project. The units depend on the Free Pascal RTL only.

```pascal
uses
  cl3;

var
  a, b, v: TVector;
  R: TMultivector;
begin
  a := 1*e1;
  b := 1*e2;
  v := 2*e1 + 3*e3;
  R := b * a;                        // rotor: twice the angle from a to b
  Writeln(v.Rotation(a, b).ToString);
  Writeln((R * v * R.Inverse).ToString);
end.
```

Spacetime algebra: a Lorentz boost is a rotor too. Here a particle at rest is
boosted to v = 0.6c along g1, and its squared norm (the invariant mass) is
preserved:

```pascal
uses
  Math, cl13;

var
  phi: double;
  p, q: TVector;
  R: TMultivector;
begin
  phi := ArcTanh(0.6);                     // rapidity for v = 0.6c
  p := 1*g0;                               // particle at rest, unit mass
  R := Cosh(phi/2) - Sinh(phi/2)*g01;      // boost rotor along +g1
  q := TVector(R * p * R.Reverse);
  Writeln(q.ToString);                     // +1.25g0 +0.75g1 (gamma, gamma*v)
  Writeln(p.SquaredNorm:0:6, ' ', q.SquaredNorm:0:6);  // 1.000000 1.000000
end.
```

### Conventions

- `Dot` is the "fat" dot product: e_A . e_B = e_A e_B when one index set contains
  the other, 0 otherwise (scalars included).
- `Involute` is the grade involution, `Conjugate` the Clifford conjugate.
- `SquaredNorm` is <X ~X>_0, `Norm` is `Sqrt(Abs(SquaredNorm))`.
- `Dual` is X * I.
- `Inverse` is the multiplicative inverse; left and right inverses coincide in
  a finite-dimensional associative algebra. Grades whose elements satisfy
  X ~X = scalar use ~X / <X ~X>_0; every other case uses the Faddeev-LeVerrier
  recurrence in the form given by D. Shirokov, valid for any signature.
  A `TMultivector` holding a single grade takes the grade-specific path, so the
  result does not depend on the type used to store the value. Dividing by a
  non-invertible value raises a floating-point exception.
- `X.Rotation(A, B)` is B A X A⁻¹ B⁻¹, the composition of two reflections: it
  rotates X in the plane A ∧ B by **twice** the angle from A to B. For example,
  with A = e1 and B at 45° from e1 towards e2, e1 is rotated to e2.
- Widening to `TMultivector` is implicit; narrowing (to a k-vector or to
  `double`) is explicit: `TVector(M)`, `double(M)`.
- `Components[...]` reads and writes single coefficients, e.g.
  `B.Components[bc12]`, `M.Components[mc123]`.

## Tests

Each unit has a test program and a self-check program in [`tests/`](tests):

```
lazbuild tests/cl3test.lpi  && tests/build/cl3test
lazbuild tests/cl3check.lpi && tests/build/cl3check
```

The self-check programs are generated together with the units (see
[Self-check program](#self-check-program)).

## Toolkit

The [`toolkit/`](toolkit) folder generates a complete, ready-to-use Free Pascal
unit for the geometric algebra Cl(p,q), with p + q between 1 and 6.

### Requirements

- Free Pascal 3.2 or later.
- Lazarus (`lazbuild`); the GUI also needs the SynEdit package, which ships
  with Lazarus. The command-line generator depends on the Free Pascal RTL only.

### Files

| File | Purpose |
|---|---|
| `clgencore.pas` | Algebra model, type inference and code emitter (no LCL dependency) |
| `clgen.lpi`, `clgen.lpr` | Command-line generator |
| `clgengui.lpi`, `clgengui.lpr`, `mainfrm.pas`, `mainfrm.lfm` | GUI: product tables, source preview, export |

### Build

```
lazbuild toolkit/clgen.lpi                     # command-line generator: toolkit/build/clgen
lazbuild toolkit/clgengui.lpi                  # GUI: toolkit/build/clgengui
```

### GUI

Choose the number of positive and negative basis vectors, the index base and
the basis prefix. The tabs show the dot, wedge and geometric product tables and
the generated source; *Export unit* saves the unit and *Export test* saves its
self-check program.

### Command line

```
clgen -p <positive> [-q <negative>] [-b <0|1>] [-n <basis prefix>]
      [-u <unit>] [-o <file>] [-t <test file>] [-i <test iterations>]
```

| Option | Meaning | Default |
|---|---|---|
| `-p`, `-q` | number of basis vectors squaring to +1 and to -1 | `-q 0` |
| `-b` | index of the first basis vector | `1` (e1, e2...) |
| `-n` | prefix of the basis names | `e` |
| `-u` | unit name | `cl<p>` or `cl<p><q>` |
| `-o` | output file | `<unit>.pas` |
| `-t` | also write a self-check program | none |
| `-i` | iterations of the self-check | chosen from the dimension |

Examples:

```
clgen -p 3 -t cl3check.lpr                     # Euclidean 3D space
clgen -p 1 -q 3 -b 0 -n g -u cl13              # spacetime algebra: g0..g3, g0^2 = +1
clgen -p 4 -q 1 -u cga3                        # conformal model of 3D space
```

### Regenerating the units of this repository

From the repository root, after building `clgen`:

```
toolkit/build/clgen -p 2 -t tests/cl2check.lpr
toolkit/build/clgen -p 3 -t tests/cl3check.lpr
toolkit/build/clgen -p 4 -t tests/cl4check.lpr
toolkit/build/clgen -p 1 -q 3 -b 0 -n g -u cl13 -t tests/cl13check.lpr
```

Then build and run the self-checks as shown in [Tests](#tests).

### Self-check program

`-t` (or *Export test* in the GUI) writes a program that verifies the generated
unit on random operands:

- metric and anticommutation of the basis vectors, every basis blade as the
  ordered product of its vectors;
- associativity, reverse and grade involution of a product, conjugate;
- wedge and dot of vectors against (ab -+ ba)/2, dual, squared norm;
- left and right inverse;
- every k-vector type against `TMultivector` for all operators and helper
  methods (this also verifies the return types chosen by the generator).

Operands are small integers, so most checks are exact. Exactly singular
operands raise a floating-point exception and are counted as skipped.

### How return types are chosen

- Products of two independent operands (`*`, `Dot`, `Wedge`, `Dual`, `+`, `-`)
  cannot cancel: the exact result type is read from the product table.
- Formulas that use the same operand more than once (`Inverse`,
  `Projection`, `Rejection`, `Reflection`, `Rotation`) are evaluated by the
  generator on random operands in modular arithmetic. Components that vanish
  identically are dropped, so for example `TVector.Rotation(TVector, TVector)`
  returns a `TVector`. Generation is deterministic.

### Declaration order

`TMultivector` is declared first, then the k-vectors by increasing grade. Every
mixed operator lives in the record declared last, so its result type is always
already declared (for example `TBivector * TTrivector` in 3D returns a
`TVector`). The generator checks this and stops with an error if it is ever
violated.
